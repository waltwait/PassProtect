# 本地備份 設計規格

日期：2026-10-24
狀態：待審

## 1. 目標

把加密的資料庫檔每天自動備份一份到手機上使用者自己選的資料夾，保留最新 30 份，並能在 app 裡挑一份還原。

現況只有 app 私有目錄裡的 `previous.kdbx.bak`（存檔前一版，每次覆蓋），刪掉 app 或清除資料就沒了。這份不動，繼續當「寫到一半失敗」的救援用。

## 2. 使用者看到的

設定頁在「資料庫」下面新增「備份」區段，三列。文字盡量少：

| 列 | 內容 | 點了 |
|---|---|---|
| 備份資料夾 | 右側：資料夾名稱，或「未設定」 | 開系統的資料夾選擇器，取得持久授權 |
| 立即備份 | 右側：最後一次備份時間（「今天 14:32」「10月22日」）；失敗時改成「備份失敗」（error 色） | 沒設資料夾時先開資料夾選擇器 |
| 從備份還原 | — | 開底部清單 |

還原清單（底部面板）：每列一份備份，最新在上，顯示日期；「還原前」的那種在日期旁標「還原前」。點一列 → 對話框：主密碼欄位、「還原」。處理中轉圈；成功就關掉面板；密碼錯顯示「主密碼不對」。

## 3. 備份規則

- **檔名**：每日備份 `PassProtect-yyyy-MM-dd.kdbx`（手機當地日期）；還原前的備份 `PassProtect-yyyy-MM-dd-HHmmss-before-restore.kdbx`。
- **時機**
  - 解鎖成功：今天的檔案還不存在就寫一份（內容是剛從磁碟讀到、解鎖用的那份位元組）。只在電腦上改、同步過來的內容也會被備到。
  - 存檔成功：用剛寫進資料庫的位元組建立或覆蓋今天那份，所以每一份是那天最後的樣子。
  - 存檔變成衝突（主檔被外部改過，沒有寫入）：不備份。
  - 立即備份：讀磁碟上目前的資料庫檔，覆蓋今天那份。
- **保留**：每次寫完後清理。只看符合上面兩種檔名的檔案，依檔名裡的日期時間排序，保留最新 30 份，其餘刪除。資料夾裡其他檔案一律不碰。
- **內容**：原封不動的 KDBX 密文，不另外加密；KeePassXC 可以直接打開。
- **失敗不擋**：寫入、刪除、讀取資料夾出錯，都不影響解鎖或存檔的結果，只把狀態記成失敗，設定頁那一列顯示「備份失敗」。下一次成功就恢復。
- 備份的檔案操作都在背景（IO）執行。
- 沒設資料夾、或授權已失效：不備份，設定頁顯示「未設定」。

## 4. 還原

1. 讀出那份備份，用輸入的主密碼解開（背景，Argon2）。密碼錯：顯示錯誤，什麼都不動。
2. 把磁碟上目前的資料庫存成「還原前」備份。這一步失敗就中止還原——沒有退路就不蓋。
3. 把備份的**原始位元組**交給 `VaultRepository.save()` 寫回主檔（不重新序列化，維持原樣），沿用既有的外部改動偵測：
   - 寫入成功：session 換成解開的那份資料庫、快取這次輸入的主密碼、更新清單，關掉面板。
   - 衝突（主檔在這段期間被外部改過）：備份內容照既有規則另存成衝突檔，session 不換，顯示既有的衝突訊息。
4. 輸入的主密碼跟目前的不同、且指紋解鎖已開啟：用新密碼重新綁定（同「變更主密碼」的做法）。
5. 還原後照第 3 節的規則更新今天的每日備份。

## 5. 實作

| 檔案 | 內容 |
|---|---|
| `storage/BackupFolder.kt` | `interface BackupFolder { list(): List<StoredFile>（檔名＋最後修改時間，供「最後一次備份時間」用）; read(name): ByteArray; write(name, bytes)（建立或覆蓋）; delete(name) }`，`SafBackupFolder`（`DocumentFile.fromTreeUri`），JVM 測試用記憶體假實作 |
| `storage/LocalBackups.kt` | 檔名產生與解析、`backupDaily(folder, bytes, today, overwrite)`、`backupBeforeRestore(folder, bytes, now)`、`prune(folder, keep = 30)`、`list(folder)`（排序後的備份清單） |
| `ui/BackupLocationPrefs.kt` | 記住資料夾的 tree URI（同 `VaultLocationPrefs` 的做法） |
| `ui/VaultViewModel.kt` | 啟動時從偏好還原資料夾；解鎖、存檔成功後的備份；`chooseBackupFolder`、`backupNow`、`refreshBackups`、`restoreBackup(name, password, biometric)`；注入日期時間的 seam 給測試 |
| `ui/VaultUiState.kt` | `backupFolderName`、`lastBackupAt`、`backupFailed`、`backups`、還原狀態（進行中／密碼錯） |
| `ui/screens/SettingsScreen.kt`、`ui/screens/RestoreBackupSheet.kt` | 「備份」區段與還原面板 |

## 6. 測試

- JVM：檔名產生與解析；保留 30 份只刪自己的檔；今天已存在時解鎖不覆蓋、存檔會覆蓋；衝突不備份；備份失敗不影響存檔結果；還原密碼錯什麼都不動；還原成功先寫「還原前」再寫主檔並換掉清單；「還原前」寫入失敗就中止；還原遇到衝突不換 session。
- 手機手動驗證：選資料夾、重開 app 後還記得；每天第一次解鎖產生當天的檔；KeePassXC 打得開備份；還原後清單換成備份的內容；用不同主密碼的備份還原後，指紋解鎖仍可用。

## 7. 不做

- 不上傳雲端、不做第二層加密。
- 不排程背景工作（WorkManager）：只在解鎖、存檔、按「立即備份」時觸發。
- 不比較備份內容、不顯示每份有幾筆（要逐份解密，太慢）。
